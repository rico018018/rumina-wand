# ハリーポッターとるみなのまほうのつえ

玩具の杖で呪文を唱えると、テレビに映した3Dの魔法世界で対応する出来事が起きる家庭内Webアプリです。
音声認識が呪文を聞き取り、**設定した待ち時間（初期値 約1秒）のあとに、その呪文に登録した色の光**が画面内に出て、
続けて演出が走ります。待ち時間のあいだに子どもが杖を振ります。

杖の動作・ボタン・成功信号・光は**いっさい検知しません**。カメラも使いません。

## いまの状態（第1段階：3呪文の実機試作）

| 項目 | 状態 |
|---|---|
| 音声で発動する呪文 | **Accio / Protego / Serpensortia の3つ**（設定で14呪文に広げられます） |
| 手動ボタンで発動する呪文 | **14呪文すべて** |
| 呪文ごとの発光色設定 | **14呪文すべて**。保存・プレビュー・書き出し・読み込み・初期値に戻す |
| 世界の状態 | ヘビ・宝物・破片などが残り、再読み込みしても引き継ぎます |
| 実機（iPhone + BRAVIA）での検証 | **未実施**。下の「まだ分かっていないこと」を参照 |

## まだ分かっていないこと（正直に書いておきます）

このリポジトリの時点で、**実機での音声認識の挙動は一度も確認できていません**。
検証は利用者の iPhone と BRAVIA でしか決まらないため、次の点は「未確認」です。
アプリ内の「わかっていること・わかっていないこと」にも同じ内容を表示しています。

- iOS Safari で `continuous = true` が効くか。効かない場合に自動の再開がユーザー操作なしで許可されるか
- 架空の単語（Accio など）が一般語へ誤変換される度合い。`en-US` と `ja-JP` のどちらが合うか
- 3歳の声・声量での認識のしやすさ
- HDMIアダプタ接続中にマイク入力が生きるか
- テレビのスピーカーから出た効果音が誤発動を招くか
- 玩具の杖の効果音が誤発動を招くか
- 長時間の発熱・コマ落ち

**保証していないこと**

- 発音の**採点**はしていません。やっているのは認識テキストの許可リスト照合です。一致を「発音が正確」とは扱いません。
- ブラウザの音声認識は端末・ブラウザ・サービス依存です。無料・連続動作・オフライン・高精度のいずれも保証しません。
- 14呪文の**実物のLED色は不明**です。初期色はすべて仮の色で、映画やゲームの色を実物として登録していません。
- テレビと杖の発光色の完全な一致は保証しません。

## 使いかた

1. 公開したURLを iPhone の Safari で開きます（マイクを使うので **https が必須**）。
2. 右上の「⚙ ほごしゃ」から保護者パネルを開き、「はじめる（きく）」を押してマイクを許可します。
3. パネルの「とじる」で遊び画面だけにします。
4. 呪文を唱えます。認識されると「つえを ふって！」と出て、約1秒後に光ります。

詳しい手順とテレビ接続の確認事項は [`docs/保護者向け手順.md`](docs/保護者向け手順.md) にあります。
実機検証の進めかたは [`docs/実機検証チェックリスト.md`](docs/実機検証チェックリスト.md) にあります。

## ローカルで動かす

ビルドもインストールも不要です。静的ファイルを配るだけで動きます。

```sh
python3 -m http.server 8777
# → http://localhost:8777/
```

`localhost` ではマイクが使えますが、**同じLANの `http://192.168.x.x` ではiPhoneのマイクは使えません**（安全なコンテキストではないため）。
iPhone で試すには https の公開URLが必要です。

## テスト

```sh
node --test test/*.test.js
```

66件。呪文の判定（matcher）、色設定の保存と検証（colors）、世界の状態遷移（world）、診断の記録（diagnostics）を対象にしています。
描画と音声認識はブラウザでしか動かないため、ここには含まれません。

## 構成

ビルド工程なし。素の ES モジュールと、同梱した three.js だけで動きます。

```
index.html          画面の骨組み
src/
  spells.js         14呪文の定義（綴り・発音ガイド・カタカナ・仮の初期色・認識候補）
  matcher.js        認識テキスト → 呪文の照合。許可リスト方式。曖昧なら失敗にする
  world.js          魔法世界の状態機械。描画も音も音声も知らない純粋なロジック
  colors.js         呪文ごとの発光色の保存・検証・書き出し・読み込み
  speech.js         音声認識のラッパー。モード切替・再開ループ・抑制・ログ
  audio.js          効果音の合成（音声ファイルなし）
  scene.js          three.js の3D世界と発動の光
  diagnostics.js    保護者向けの診断・試験記録・認識候補の追加
  app.js            発動パイプライン（認識 → 待ち時間 → 登録色の光 → 演出）
  ui.js             画面の配線
  styles.css        見た目
vendor/             three.js r186.1（CDN非依存。vendor/README.md 参照）
test/               Node の標準テストランナー用
docs/               保護者向け手順・実機検証チェックリスト
```

**音声発動と手動発動は同じ道を通ります。** どちらも `app.js` の `castSpell()` から `world.js` の `applySpell()` へ入り、
同じ演出・同じ状態変更・同じ色設定を使います。音声が不調でも手動で遊びを続けられます。

### 設計上の約束

- **「認識の失敗」と「対象がない」を分ける。** 正しく唱えたのに岩がない、すでに起きている、上限に達した——これらは
  失敗演出を出さず、穏やかな合図にします（`world.js` の `status`: `applied` / `no_target` / `already` / `at_cap`）。
- **無音は失敗ではない。** 発話を受け付けて一致しなかったときだけ失敗演出を出します。権限拒否・通信エラーも別扱いです。
- **一番近い呪文へ勝手に寄せない。** `matcher.js` は許可リストの照合だけを行い、複数の呪文に同じ距離で一致したら失敗にします。
  既定の厳しさは「きびしい（完全一致のみ）」です。
- **色設定は消さない。** 世界の初期化、Finite Incantatem、入力モードの変更では色設定に触れません。保存キーも別です。
- **待ち時間のあいだに登録色を出さない。** 待ち時間中は中立色の「ためる」表示だけで、色は待ち時間のあとに出ます。
